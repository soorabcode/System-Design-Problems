# System Design Problems

A collection of practical **System Design interview problems**, covering the design of scalable, reliable, and high-performance systems.

This repository documents system design problems step by step, from requirement analysis and API design to system architecture, database design, and low-level design. The goal is to build a structured reference for learning system design and preparing for technical interviews.

## Problems

This repository focuses on commonly discussed system design problems, with each problem organized into its own directory.

| # | Problem | Description | Solution |
|---|---|---|---|
| 1 | **TinyURL — URL Shortener** | Design a service that converts long URLs into short links and redirects users to the original URLs. | [View Solution](./TinyURL/Readme.md) |

More system design problems will be added as the collection grows.

## What Each Solution Covers

Depending on the problem, the design documentation may include:

- **Requirement Analysis** — Functional and non-functional requirements
- **Capacity Estimation** — Traffic, storage, and scalability estimates
- **Entity Identification** — Core entities and their relationships
- **API Design** — Endpoints, requests, and responses
- **High-Level Design (HLD)** — Major components and their interactions
- **Low-Level Design (LLD)** — Detailed component and data-model design
- **Database Design** — Schema, indexes, and data access patterns
- **Scalability and Reliability** — Caching, load balancing, replication, and failure handling
- **Trade-offs** — Design decisions and alternative approaches

The exact sections depend on the requirements of each problem.
